# 安装与更新

## 首次安装

从 [Releases](https://github.com/AoralsFout/thmr-filter-node/releases) 下载 `thmr-node-<版本>-windows-x64-install.zip`，解压到本机目录并运行 `Install.cmd`。

程序默认安装到 `%LOCALAPPDATA%\THMR-Filter-Node` 并创建桌面快捷方式。首次安装从上游获取 FFmpeg/ffprobe 与 7zr，不从本仓库下载这些工具的二进制；工具下载使用固定版本、文件大小与 SHA256 校验。安装完成后打开本机工作台。

下载中断时，先检查网络，再在安装目录运行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\setup-tools.ps1
```

随后双击桌面快捷方式。若首次下载失败时尚未生成快捷方式，在安装目录运行以下命令启动工作台：

```powershell
& .\launcher\thmr-node.exe --install-root (Get-Location).Path
```

若需要自行配置工具，可以在运行安装器时指定 `-SkipTools`；对应工具缺失时节点不会通过音频环境自检。

安装器拒绝覆盖已有安装。已有节点通过更新器升级；需要全新安装时，使用 `install.ps1 -InstallDir <新的安装目录>`。不要把已有节点的配置复制给其他人。

## 从 0.3.x 重新安装

0.4.0-beta.1 使用结构 100 和协议 2，不接受 0.3.x 数据目录，不提供跨结构自动升级。先停止旧节点并保留其安装与数据，再下载新的安装 ZIP，在解压目录运行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\install.ps1 -InstallDir "$env:LOCALAPPDATA\THMR-Filter-Node-0.4"
```

在打开的工作台选择新的空数据目录，使用新的邀请码重新登记；不要复制旧版 `node.json` 或数据库。新机器同样使用独立身份和数据目录。已有同结构的 0.4.x 安装可使用签名更新器。

## 接入与停止接单

填写维护者提供的中央 HTTPS 地址与一次性邀请码，选择新的空数据目录、缓存预算、保留空间和并发预设。网络中断时可使用相同目录重试，已保存的接入凭证用于恢复申请。

环境自检通过后仍需维护者批准。未批准、能力不足、空间不足、中央调度暂停或本机停止接单时，都不会开始新任务。

在工作台选择「停止接单」，当前任务继续完成；选择「立即暂停」则请求暂停当前任务。任务是否再次运行由中央安排。

## 可选模型

基础程序不要求 Python。需要模型时，先准备本机 CPython 3.12，再在安装目录运行：

```powershell
.\setup-models.ps1 -Python C:\Python312\python.exe -Device cpu
```

NVIDIA CUDA 分类节点可使用 `-Device cuda`。脚本在所选数据目录创建独立环境并下载分类模型；可用 `-SkipClassifier` 跳过分类权重。下载会使用网络和磁盘，模型依赖较大。完成后重启节点，在设置中选择设备并主动启用模型。

CUDA 讲话检测额外需要已转换并验证的 ONNX 权重，本测试包未替参与者完成该转换或硬件验证。分类权重来自 MTG/Essentia，适用其独立许可，下载脚本会保留来源与许可信息。

## 更新与数据保留

在「本机设置 → 程序更新」查看状态或关闭自动升级。测试版默认使用 beta 通道；切换到其他通道前先完成当前任务，并与维护者确认兼容版本。

程序按版本保存在安装目录 `releases/`，实际数据目录可在首次接入时另选。更新器保留配置、待回传结果、音频、缓存和模型，下载失败时继续运行旧版本。不要手动删除仍被当前版本引用的程序目录。

## 问题反馈

日志位于安装目录的 `launcher.log` 和 `worker.log`。提交问题时只附复现所需片段，并删除凭证、私人路径和不希望公开的资料；不要上传 `node.json`、`config.json` 或完整数据目录。

卸载前先停止节点进程，按需保留数据目录，再移除安装目录和桌面快捷方式。删除数据目录会删除本机凭证、音频缓存和模型。
