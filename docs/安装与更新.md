# 安装与更新

## 首次启动

从 [0.4.0-beta.2 发布页](https://github.com/AoralsFout/thmr-filter-node/releases/tag/v0.4.0-beta.2) 下载 `thmr-node-0.4.0-beta.2-windows-x64-portable.zip`，解压到本机目录，双击根目录的 `thmr-node.exe`。不要直接从压缩包内运行程序。

解压位置就是程序位置。基础运行环境、FFmpeg/ffprobe 与解包工具已经提供；不需要安装 Python、Node.js 或 Git，不自动创建快捷方式或开启开机启动。

## 从旧版本重新接入

beta.2 使用便携发行格式 1，中央结构 100、元数据协议 2。它不接管 beta.1 或 0.3.x 的旧安装布局、配置与节点身份，也不提供旧库迁移。

先停止接单并等待工作流与待回传成果排空，使用旧程序的退出入口关闭进程，保留原目录，再将新便携包解压到新位置。首次接入明确选择新的空数据目录，使用新邀请码或计算凭证登记。不同机器不得复用节点身份。

## 接入与接单

在本机网页选择社区节点或可信节点，填写维护者提供的中央 HTTPS 地址、节点名称，以及一次性邀请码或可信节点计算凭证，选择新的空业务数据目录与资源预算。

社区节点完成音频自检后等待管理员批准。首次接入保持停止接单，模型与付费 API 关闭，不自动配置下载器。检查能力、磁盘空间和并发设置后主动恢复接单；中央调度也须开启才会领取新任务。

「停止接单」让当前任务继续完成；「立即暂停」请求中断当前工作流；恢复接单不会自动恢复已经暂停的任务。

## CPU 与 CUDA 模型

进入「本机设置 → 程序与环境」，查看程序和数据位置，选择 CPU 或 CUDA 并确认资源、磁盘需求和下载位置。在线准备和离线导入使用相同清单，检查大小、SHA256 和逐文件内容，真实推理自检通过后才激活。失败时保留原环境。

离线下载本次版本的资源：CPU 选择完整 ZIP；CUDA 将三卷 `.zip.001`、`.002`、`.003` 放在同一目录，在工作台选择 `.001`。分卷缺失或校验失败时不会激活。资源很大，下载页列出的压缩文件大小不包括展开、缓存和重建所需空间。

CPU/CUDA 分别管理。CUDA 需要兼容的 NVIDIA 驱动，程序只检查，不自动安装或升级。资源包含固定 Python、依赖和权重，不要求参与者自行安装 Python、运行 pip 或转换模型。准备完成后主动启用所需模型。

需要修复时在同一入口选择重建，复用完整缓存并保留配置、权重和业务数据。也可使用便携根目录的 `Repair-Models.cmd`，或 `Repair-Models.ps1 -Device cpu|cuda`，按提示确认。

## 更新、移动与退出

在「本机设置 → 程序更新」检查更新、确认下载或选择自动升级。测试版使用 beta 通道；签名、有效期、序号、平台和文件摘要通过后才准备新版本。切换前停止接单并等待工作流、执行线程与待回传成果完成；健康检查失败会恢复上一程序版本。

更新不覆盖独立模型环境或业务数据。不要手动删除仍被当前版本引用的 `releases/` 目录。

网页和托盘均提供「退出程序」。默认等待任务和回传排空；断网时显示阻塞原因，可主动中断。仅关闭网页不等于退出程序。

移动程序前先完整退出，移动后检查模型环境；业务数据仍按原绝对路径访问。数据磁盘缺失时不会新建替代曲库，可重新选择身份匹配的原目录。跨电脑复制应按新节点接入，同一业务目录不能同时由两个程序副本使用。

## 问题反馈与移除

日志位于便携目录。提交问题只附复现所需片段，删除凭证、私人路径和不希望公开的资料，不上传 `node.json`、`config.json` 或完整业务目录。

移除前先完整退出并按需备份业务目录，再删除便携程序目录。删除业务目录会丢失节点身份和本机业务资料；删除便携目录也会移除其中的模型环境与资源缓存。
